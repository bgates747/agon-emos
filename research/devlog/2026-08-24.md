## EMOS-105 — safe transient dispatch

Completed with one synchronous transient invocation boundary.

- Core rejects absent providers, concurrent/nested calls, unsafe policies, and
  any input, output, gateway-request, wraparound, or nonzero-length range that
  intersects the 32 KiB module area.
- A selected file is loaded at `0x0B0000`, then its complete header, header
  CRC, payload CRC, fixed request-size compatibility, identity, version,
  bounds, and discovery-time fingerprint are revalidated before calling only
  the fixed ADL entry.
- Providers receive a Core-local 24-byte request. Mutation of its immutable
  prefix/reserved byte, an output length beyond capacity, or an out-of-range
  provider status maps to bounded `EMOS_PROVIDER_FAILED`. No transient code or
  data pointer is returned by a public gateway.
- One busy flag excludes discovery, clear, replacement, nested service calls,
  and mode changes for the complete invocation. External modules own no
  interrupt vector or callback. After return or load failure, Core scrubs the
  module area; the compatible-application path restores it instead.
- Boundary/wrap, request-range, reload-fingerprint, teardown, and structural
  exclusion tests pass. Regenerated firmware verifies at 110,422 bytes.

## EMOS-106 — application eligibility and preservation

Completed without changing whether MOS executes an existing program.

- `mos_runBin` classifies policy around the existing Z80/ADL dispatch and
  restores the caller's prior policy afterward. Unaware or denied programs
  still follow MOS's pre-existing execution decision; only module-backed
  services are unavailable to them.
- Advanced-header version 1 ADL images require a valid inverse flag byte, no
  reserved bits, exactly one of module-safe or module-compatible, and either no
  optional load address or the actual address. Z80, version-0, malformed,
  unheadered, conflicting, unaware, and moslet callers cannot load a provider.
- Compatible calls synchronously save and `f_sync` all 32 KiB to the reserved
  `/.emos-swap.bin` before changing memory, then restore all 32 KiB. Save
  failure removes a partial file without loading a provider. Restore failure
  retains recovery state, returns `EMOS_RECOVERY_FAILED`, blocks implicit
  request replay, and permits a later restoration attempt while the application
  remains live. Exit or cold boot discards preservation without a live owner.
- Eighteen focused tests include the eligibility matrix, buffer boundaries,
  save/provider/restore failure ordering, and target integration structure.
  Regenerated firmware verifies at 110,691 bytes.

## EMOS-109 — operating-mode coordinator

Completed with physical transport deliberately unavailable.

- One committed state records formal mode, ordinary-VDU route, EDU active
  state, and generation. Its four shapes are exactly Legacy `(onboard,off)`,
  Dual `(onboard,on)`, Exclusive Compatible `(compatible EDP,on)`, and
  Exclusive Extended `(extended EDP,on)`.
- Legacy is the hub. A non-Legacy-to-non-Legacy request fails without mutation.
  Entry runs prepare, readiness, adapter commit, then one logical publish and
  one-byte route commit. Failure runs bounded recovery and retains the prior
  published state.
- Cold boot selects the unavailable adapter and operational Legacy. The
  explicitly selected fake adapter supports only Dual, maintains its own EDU
  state/result fields, and leaves ordinary VDU onboard. It rejects both
  exclusive modes rather than pretending to implement a physical backend.
  Adapter selection can change only in Legacy.
- The mode oracle covers all four shapes, unavailable recovery, fake Dual,
  exclusive denial, direct-transition denial, and Legacy recovery. Target
  structure tests verify adapter call order, separate EDU storage, and final
  route publication. Regenerated firmware verifies at 111,560 bytes.
