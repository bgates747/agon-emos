# E03 — Stock reuse and linked execution audit

Completed 2026-09-14 UTC. Analysis only; no maintained firmware source, build
profile, executable or deployment changed. E04 requires the next supervised
approval. This report fulfils E03 of [INTEG-014](../INTEG-014.md); it is not a
second task list or an optimisation result.

## Findings for review

1. The forward byte path repeats substantial bookkeeping before discovering
   that a byte can be sent immediately. The E02 ELF still contains ten nested
   helper calls on that successful path, plus the caller's per-byte call.
   Stock's CTS/THRE/THR sequence is the right implementation model, with EMOS's
   ownership, timeout and receive-error requirements retained.
2. Receive backpressure has a concrete software explanation to investigate:
   UART1 stops its peer while draining and parsing up to 16 bytes, including
   completed-packet effects. Both UART handlers also save registers needed by
   C. These are established operations, not measured attribution of all delay.
3. Most added functionality is not a second implementation of stock services.
   EMOS already uses stock command parsing, FatFS, allocator, output, keyboard
   effects and display effects. Its largest object includes an additional
   module system that stock MOS 3.0.2 does **not** implement. That distinction
   matters when deciding what belongs in a thin wrapper.
4. There are smaller consolidation candidates: repeated deadline arithmetic,
   diagnostic command scaffolding, registry sorting and address validation.
   Their actual image savings remain unmeasured. The clearest first C candidate
   is a native-width private stalled-clock counter: its maximum 262,144 fits
   in 24 bits, whereas the present 32-bit operation calls runtime helpers.
5. Ordinary EMOS still has only **157 flash bytes free**. Diagnostic objects
   occupy 4,948 bytes and parallel objects 3,059, but excluding supported
   functions is a composition decision, not a same-functionality optimisation.
   No feature has been removed or moved into application-owned SRAM.

[console](../../../src/emos_console.c),
[keyboard transport](../../../src/emos_keyboard.c), and
[UART driver](../../../src/uart.c). Stock counterparts are
`src_startup/vectors16.asm` and `src/serial.asm`.

| Operation/frequency | Stock MOS | Current EMOS ordinary / bench |
|---|---|---|
| Counted VDU entry, once per block | Assembly pointer/count loop calls UART0 PUTCH per byte | Backend selector 19 bytes; ExCom assembly bridge 37 bytes; C stream gate 48 bytes; sender 191 bytes. These sizes agree across both EMOS compositions. Bridge saves/marshals once per block, not per byte. |
| Buffer iteration, once per byte | Load `(HL)`, PUTCH, increment pointer, decrement count | C loop loads/indexes source, preserves loop state around `_transmit`. No complete outgoing-block copy or per-byte framing envelope. |
| CTS/THRE/THR, each attempt | UART0 CTS wait 8 bytes; UART1 GPIO CTS wait 9. UART0 TX full range 29 bytes (6+16+7); PUTCH 25. Short register/poll sequence, with TX retry inside PUTCH | `_transmit` 71 bytes calls `_deadline_step` 127 and `_uart1_keyboard_put` 106. Owner/fault checks, error-aware LSR read, PC3 CTS, THRE and THR write under a short IFF-preserving lock. Same sizes ordinary/bench. |
| Timeout bookkeeping, every attempt including ready UART | TX counter initialised per byte; decremented while THRE unavailable. Five-second whole-call policy at the current 60 Hz clock; not an idle-only deadline. |

Healthy first-attempt write with an unchanged MOS clock, ordinary ELF:

| Caller | Executed direct calls (call-site address → target) | Count |
|---|---|---:|
| Sender loop | `0x6c65 → _transmit` | 1 |
| `_transmit` | `0x6811 → __frameset0`; `0x6822 → _deadline_step`; `0x682e → _uart1_keyboard_put` | 3 |
| `_deadline_step` | `0x673d → __frameset`; `0x6741 → _emos_keyboard_clock`; `0x6780 → __ladd`; `0x678d → __lcmpzero` | 4 |
| `_uart1_keyboard_put` | `0x12a8b → __frameset`; `0x12a94 → _emos_keyboard_lock`; `0x12ae4 → _emos_keyboard_unlock` | 3 |
| **Total, excluding once-per-block setup and calls inside runtime helpers** | | **11** |

The additional `_uart1_keyboard_stop` call at `0x12ad5` is error-only and is
excluded. A changed clock bypasses the long decrement/test. Blocked attempts
repeat the deadline and UART portions; do not multiply all once-per-byte setup
by every polling iteration. For stock counted output with hardware flow enabled,
there is one PUTCH call plus its CTS and TX calls on a ready first attempt.
These call counts are not a cycles or throughput ratio.

`__frameset`/`__frameset0` are 14/11 bytes; `__ladd`/`__lcmpzero` are 6/11.
All exist in stock's same-size restricted runtime. The placement and frequency
of calls, stack slots and indexed loads matter more than their small ROM sizes.
The candidate is to reduce repeated work first, then compare C versus assembly
only if measurements justify it.

A direct call to public UART1 PUTCH is **not** a valid replacement: EMOS guards
those APIs while its resident receiver owns the UART. Stock blocking semantics
also cannot silently replace EMOS's bounded failure policy. LSR reads can
acknowledge receive errors; any fast path must preserve their handoff to the
resident receiver. UART0 CTS uses MSR, UART1 CTS uses PC3 GPIO; changing only
the UART base address is insufficient.

|---|---|---|---|
| UART0 IRQ entry/exit, each received byte IRQ | Handler 26 bytes; four PUSH/four POP; RX and parser calls | Handler 46 bytes; ten PUSH/ten POP plus alternate-bank exchanges | Six additional save/restore pairs execute even when a later packet effect is suppressed. Needed by the current C/callback path; investigate moving saves to the branch that needs them, not deleting protection. |
| UART1 IRQ entry/exit | No resident stock UART1 VDP receiver to compare; application owns vector | Assembly entry 37 bytes, ten PUSH/ten POP, C receiver call | Stock UART0 gives the structural comparison, not an existing drop-in UART1 service. |

Bench adds async TX call | Packet effects occur while peer is stopped. Batching amortises entry overhead but cannot by itself establish good throughput. Measure occupancy and completion effects separately. |
| Frame parsing, each byte | Four-state assembly parser with one global 16-byte payload | C byte parser 412 bytes both; independent 240-byte payload, length-directed discard, type checks, whole-frame age limit | Reuse parsing logic only with separate contexts and reviewed length behaviour; sharing stock globals corrupts interleaved incomplete UART0/UART1 packets. | Non-key reply effect, each completed eligible packet | Stock effect handlers write existing sysvars | Console packet handler 473 bytes plus `_effect` 87; save 16 stock payload bytes, copy new payload, call stock effect, restore 16 | Existing reuse adapter protects a partially assembled UART0 packet. | Keyboard event, each selected packet | Stock callback then key/map publication | Shared pointer-based stock effect, callback edits retained; private held-key tracking and synthetic releases | Necessary source switching state. | VBlank housekeeping, once per tick | Existing clock/repeat handling | Adds 25-byte bridge and C tick 124 / 182 bytes | Partial-frame expiry/source cleanup, plus optional bench asynchronous sender. Do not infer per-byte cost or suppress the stock clock in production. |
| Foreground VDP wait | `wait_VDP` 37 bytes, fixed iteration wait on global packet flags | Stock helper retained unchanged; console wait 187 bytes adds private flag/fault/clock policy | Stock helper does not supply the required private transaction deadline semantics. The mainboard clock advances by two units at each 60 Hz VBlank; 600 units are
about five seconds, and the 30-unit partial-frame limit is about 250 ms.
Do not label these values milliseconds or use nominal centiseconds to derive
precise timing without accounting for the selected video mode.

## Refresh of earlier findings and pitfalls

1. AUDIT-005 W2's partial-write finding used an older source. Current
   `emos_keyboard_send` sets `fault_requested` on any failed transmission, and
   the E02 ELF contains that store at `0x6c80`. **Do not report the missing
   assignment as a current bug.** Cleanup is deferred to the interrupt tick;
   admission before that tick deserves an explicit failure/retry check in the
   implementation step. This audit does not prove every replay window closed.
2. Current keyboard tests now call `emos_keyboard_send` in the bench variant
   for busy and successful-send cases. They still do not directly establish
   the ordinary counted sender's partial-timeout/retry behaviour. Older wording
   that no harness calls the sender at all is stale. No new tests were run here.
3. EMOS's existing stock parser fork includes the earlier oversized-packet
   discard-length correction, plus bounded diagnostic callback dispatch and
   backend filtering. Blindly replacing it with tagged stock would regress
   known behaviour. No upstream bug was fixed as part of this audit.
4. IFF-off ordinary ExCom writes return BUSY; stock raw PUTCH does not have
   that policy. Preserve/explicitly review this compatibility boundary. Never
   enable interrupts behind an ISR caller's back to gain performance.
5. Callback edits remain authoritative; ISR routines must preserve registers
   used by interrupted C and assembly. Saving fewer registers requires proving
   the reachable call graph, not assuming callbacks are well behaved C.
6. Earlier wire evidence now establishes no P4 backpressure in the measured
   forward window and substantial Agon RTS blocking in the reverse window.
   Old unknown-P4-permission wording is superseded. UART0 was not sniffed;
   simultaneous ESP32 traffic remains a hypothesis to test.
7. Flash, reserved external SRAM, available heap and the 8 KiB application-owned
   on-chip SRAM are different budgets. No relocation or bootstrap was selected.
