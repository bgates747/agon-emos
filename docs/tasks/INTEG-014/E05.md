# E05 — Transmit implementation experiments

## Executive summary

E05 confirms a **33.41% reduction in Extender upload time** using small C
changes:65,535bytes now take **1,399.096ms**, against E04's2,101.076ms.
Six endpoint observations and three independently decoded wire captures exceed
the frozen5% improvement floor. All384 selected cases and eight preliminary
cases pass exact-byte/recovery checks. Mainboard timing is unchanged.

Receive time remains109.606ms on the wire; it was not fixed by TX changes.
About826.6ms of forward sender idle also remains. E06 can proceed: no new
correctness or recovery failure prevents it. The fixed diagnostic ESP pair and
verified candidate ROM remain installed for that authorised continuation;
original-image restoration and the spoken checkpoint follow E06.

## Candidate boundaries

All candidates retain the five-second whole-call deadline, the 262,144-attempt
stopped-clock limit, per-attempt UART ownership/fault checks, active-low GPIO
CTS, THRE polling and acknowledged LSR error handling. The block remains
interruptible; each hardware put retains the existing IFF-preserving lock.
Callbacks, parser state and packet effects are unchanged. The zero-length
sender and IRQ-off BUSY boundary remain unchanged.

| Candidate, cumulative | C change | Ordinary flash bytes | Bench flash bytes | Change from E04 bytes |
|---|---|---:|---:|---:|
| E04 | Original | 130,915 | 130,071 | 0 |
| native24, `c9d1e7d` | Countdown fits native 24 bits; avoid two 32-bit helper calls per attempt | 130,863 | 130,019 | -52 |
| clock-change, `9e0f8f1` | Write elapsed/last-clock fields only when the clock advances | 130,856 | 130,012 | -59 |
| block-loop, `53bdbe3` (rejected) | One C transmit frame per counted block; retain single-byte control wrapper | 130,890 | 130,046 | -25 |

These are measured whole-image sizes, not summed symbol estimates. The two
compositions keep their previous features; telemetry still replaces UARTFLOW
only in the existing explicit bench composition. New experimental images use
`agon-emos-v0.1.17` and unique build timestamps supplied through the canonical
wrappers. Maintained identity/profile edits from BENCH-001 remain preserved.

The initial block-loop candidate is **rejected before deployment**: retrying
`*data` could reload a byte changed by an interrupt, whereas the original byte
helper retained its argument across waits. A new mutation-during-stall test
fails that candidate and passes the baseline and corrected `block-retain`
variant. Preserve the failed build as evidence, never select it for hardware.

Corrected block-retain (`c15f240`) occupies130898 ordinary /130054 bench:
17bytes less than E04 in each composition. It preserves the original per-byte
value across stalls.

## Local verification

The new `tests/emos_tx_harness.c` executes the real sender against controlled
UART/clock boundaries in both compositions with ASan/UBSan. It checks exact
payload order, zero length, IRQ-off rejection, loss of ownership, partial errors,
ISR fault, CTS/FIFO stalls, whole-call timeout, stopped-clock attempt count,
clock wrap and deferred cleanup. The unchanged sender also passes these tests.
The UART-register implementation remains unchanged in these candidates.

All eight canonical firmware builds and linked checks pass, including physical
UART divisor validation. Full repository tests, when pointed at the explicitly
prepared ordinary EMOS worktree, pass 90 of 91. The remaining pre-existing
`test_product_profile_declares_emos_source_and_object_once` expects a source
list without the already-dirty telemetry entry. Neither that test nor profile
was changed to hide the mismatch. An initial invocation selected the stock
prepared worktree and was corrected; its extra failures were setup errors.

Existing deferred partial-write cleanup is preserved, including its previously
recorded admission-window limitation. A simulated lost UART owner must not
expect cleanup to manipulate hardware belonging to another owner. These are
scope boundaries, not newly fixed behaviors.

## Selected-candidate sample contract

Before seeing block-retain timing, freeze one preliminary four-row `wire` run
as an admission check, excluded from the acceptance medians. Then run one
unchanged full336 matrix, one mixed36 matrix and three independently captured
wire4 invocations. This supplies **six** primary PRNG65,535 forward endpoint
observations (three full-matrix repeats plus three wire invocations), three
independent primary wire windows, and exact-byte controls across all original
payload sizes and patterns. It avoids a second full matrix merely to repeat
non-primary cells; those cells have three observations, not six.

Both selections call the same forward function with the same seed, buffer
clear, framing, payload, baud and mode. Preserve invocation origin in the ledger
and report their ranges separately if the contexts differ materially. Compare
against E04's frozen primary medians/thresholds. Do not add runs selectively to
rescue a marginal result. The preliminary native24 comparison remains one
observation; the clock-change-only intermediate has linked evidence only.

## Attribution and next decision

Native-width arithmetic alone removed337.728ms in its preliminary run.
Avoiding unchanged clock-field writes plus block-loop consolidation removed
another364.253ms in the preliminary comparison. There is no isolated hardware
measurement for the clock-write intermediate, so do not split that combined
saving between the latter two changes. Native width removes two arithmetic
helper calls per attempt; block consolidation removes per-byte transmit entry
and its C frame setup. The healthy bulk attempt goes from11calls to7; UART
locking/error handling and deadline/clock work remain.

No assembly implementation was selected or benchmarked in E05. The meaningful
C improvement establishes a lower-cost reference for E06; it does not establish
C/assembly equivalence. E07 retains the decision on a further bounded hot-loop
comparison if the remaining sender cost merits it. Do not rewrite receive or
locking semantics merely to remove the remaining calls. The rejected first
block-loop retry behavior remains recorded above, with its passing regression
in the corrected candidate.
